# 数据库设计说明书

## 1. 设计目标

数据库用于保存 BF羽毛球馆管理平台的核心业务数据，包括用户、场地、预约、公告、系统配置和操作日志。设计目标是保证数据结构清晰、业务状态可追踪，并能支持普通用户预约和管理员后台管理。

## 2. 命名规范

- 表名使用小写英文和下划线。
- 主键统一使用 `id`。
- 创建时间统一使用 `created_at`。
- 更新时间统一使用 `updated_at`。
- 状态字段统一使用 `status`。
- 删除操作优先使用状态控制，避免直接物理删除关键业务数据。

## 3. 核心实体关系

```text
user 1 --- n reservation n --- 1 court

announcement 独立保存公告信息
config       独立保存系统规则
operation_log 记录用户和管理员关键操作
```

## 4. 数据库表设计

### 4.1 用户表 user

用途：保存普通用户和管理员账号信息。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigint | primary key, auto increment | 用户ID |
| username | varchar(50) | not null, unique | 用户名 |
| password_hash | varchar(255) | not null | 加密后的密码 |
| nickname | varchar(50) | null | 昵称 |
| role | varchar(20) | not null | 角色，user/admin |
| contact | varchar(50) | null | 联系方式 |
| status | tinyint | not null, default 1 | 状态，1启用，0禁用 |
| last_login_at | datetime | null | 最近登录时间 |
| created_at | datetime | not null | 创建时间 |
| updated_at | datetime | not null | 更新时间 |

建议索引：

- `uk_user_username(username)`
- `idx_user_role(role)`
- `idx_user_status(status)`

说明：

- 任务书中的 `password` 字段在实现时建议改为 `password_hash`，避免误解为明文密码。
- `role` 使用字符串便于阅读，也可以在实现中改成枚举值。

### 4.2 场地表 court

用途：保存羽毛球场地基础信息。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigint | primary key, auto increment | 场地ID |
| court_name | varchar(100) | not null | 场地名称 |
| court_no | varchar(50) | not null, unique | 场地编号 |
| description | varchar(255) | null | 场地说明 |
| status | tinyint | not null, default 1 | 状态，1启用，0停用 |
| price_per_hour_cents | int | not null, default 12000 | 每小时价格，单位分 |
| image_url | varchar(500) | null | 场地展示图片地址 |
| tags | varchar(255) | null | 场地展示标签，逗号分隔 |
| capacity | int | not null, default 6 | 建议容纳人数 |
| created_at | datetime | not null | 创建时间 |
| updated_at | datetime | not null | 更新时间 |

建议索引：

- `uk_court_no(court_no)`
- `idx_court_status(status)`

说明：

- `court_no` 用于前端展示和管理员识别。
- 停用场地不能新增预约。
- `image_url` 当前支持 URL 或项目内置路径，例如 `/courts/default-court.png`。
- `tags` 在接口层转换为数组返回，数据库中用逗号分隔保存。

### 4.3 预约表 reservation

用途：保存用户预约记录。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | bigint | primary key, auto increment | 预约ID |
| reservation_no | varchar(64) | not null, unique | 预约编号 |
| user_id | bigint | not null | 用户ID |
| court_id | bigint | not null | 场地ID |
| reserve_date | date | not null | 预约日期 |
| start_time | time | not null | 开始时间 |
| end_time | time | not null | 结束时间 |
| time_slot | varchar(50) | not null | 展示用时间段，例如 09:00-10:00 |
| status | varchar(20) | not null | 状态 |
| remark | varchar(255) | null | 备注 |
| price_per_hour_cents | int | not null, default 12000 | 创建预约时的场地小时价格快照，单位分 |
| duration_minutes | int | not null, default 60 | 预约时长，单位分钟 |
| original_amount_cents | int | not null, default 12000 | 原始金额，单位分 |
| discount_amount_cents | int | not null, default 0 | 优惠金额，单位分 |
| payable_amount_cents | int | not null, default 12000 | 应付金额，单位分 |
| created_at | datetime | not null | 创建时间 |
| updated_at | datetime | not null | 更新时间 |
| canceled_at | datetime | null | 取消时间 |

建议索引：

- `uk_reservation_no(reservation_no)`
- `idx_reservation_user(user_id)`
- `idx_reservation_court_date(court_id, reserve_date)`
- `idx_reservation_status(status)`
- `idx_reservation_slot(court_id, reserve_date, start_time, end_time)`

预约状态建议：

| 状态 | 说明 |
| --- | --- |
| pending | 待确认，适合后续接入支付或人工确认 |
| confirmed | 已确认，表示时间段已被正式占用 |
| canceled | 已取消 |
| expired | 超时释放 |
| completed | 已完成 |

说明：

- 当前任务书没有要求支付功能，因此基础版本可以在预约成功后直接写入 `confirmed`。
- 金额字段是预约创建时的快照。后续修改场地价格不会覆盖历史预约金额。
- 如果需要体现“超时未确认自动释放”，可以先写入 `pending`，确认后再改为 `confirmed`。
- 有效预约状态通常包括 `pending` 和 `confirmed`，冲突校验时需要排除 `canceled`、`expired`。

## 5. 建表 SQL 草案

以下 SQL 可作为后续开发的初始版本，实际实现时可根据 ORM 或迁移工具调整。

```sql
CREATE TABLE user (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50) NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  nickname VARCHAR(50) NULL,
  role VARCHAR(20) NOT NULL DEFAULT 'user',
  contact VARCHAR(50) NULL,
  status TINYINT NOT NULL DEFAULT 1,
  last_login_at DATETIME NULL,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_user_username (username),
  KEY idx_user_role (role),
  KEY idx_user_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE court (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  court_name VARCHAR(100) NOT NULL,
  court_no VARCHAR(50) NOT NULL,
  description VARCHAR(255) NULL,
  status TINYINT NOT NULL DEFAULT 1,
  price_per_hour_cents INT NOT NULL DEFAULT 12000,
  image_url VARCHAR(500) NULL,
  tags VARCHAR(255) NULL,
  capacity INT NOT NULL DEFAULT 6,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_court_no (court_no),
  KEY idx_court_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE reservation (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  reservation_no VARCHAR(64) NOT NULL,
  user_id BIGINT NOT NULL,
  court_id BIGINT NOT NULL,
  reserve_date DATE NOT NULL,
  start_time TIME NOT NULL,
  end_time TIME NOT NULL,
  time_slot VARCHAR(50) NOT NULL,
  status VARCHAR(20) NOT NULL,
  remark VARCHAR(255) NULL,
  price_per_hour_cents INT NOT NULL DEFAULT 12000,
  duration_minutes INT NOT NULL DEFAULT 60,
  original_amount_cents INT NOT NULL DEFAULT 12000,
  discount_amount_cents INT NOT NULL DEFAULT 0,
  payable_amount_cents INT NOT NULL DEFAULT 12000,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  canceled_at DATETIME NULL,
  UNIQUE KEY uk_reservation_no (reservation_no),
  KEY idx_reservation_user (user_id),
  KEY idx_reservation_court_date (court_id, reserve_date),
  KEY idx_reservation_status (status),
  KEY idx_reservation_slot (court_id, reserve_date, start_time, end_time),
  CONSTRAINT fk_reservation_user FOREIGN KEY (user_id) REFERENCES user(id),
  CONSTRAINT fk_reservation_court FOREIGN KEY (court_id) REFERENCES court(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE announcement (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(100) NOT NULL,
  content TEXT NOT NULL,
  status TINYINT NOT NULL DEFAULT 1,
  created_by BIGINT NULL,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  KEY idx_announcement_status (status),
  KEY idx_announcement_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE config (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  config_key VARCHAR(100) NOT NULL,
  config_value VARCHAR(255) NOT NULL,
  description VARCHAR(255) NULL,
  updated_by BIGINT NULL,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_config_key (config_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE operation_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NULL,
  username VARCHAR(50) NULL,
  role VARCHAR(20) NULL,
  module VARCHAR(50) NOT NULL,
  action VARCHAR(50) NOT NULL,
  target_type VARCHAR(50) NULL,
  target_id BIGINT NULL,
  detail TEXT NULL,
  ip VARCHAR(50) NULL,
  created_at DATETIME NOT NULL,
  KEY idx_operation_log_user (user_id),
  KEY idx_operation_log_module (module),
  KEY idx_operation_log_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 6. 预约冲突判断

预约冲突判断需要同时考虑 Redis 和 MySQL：

1. Redis 先加锁，锁 key 建议为 `reservation:lock:{court_id}:{reserve_date}:{start_time}:{end_time}`。
2. 加锁成功后进入 MySQL 短事务。
3. 事务内锁定当前用户行和场地行，重新确认用户、场地状态，并读取场地价格。
4. 事务内查询该用户当天有效预约，用于校验每日预约次数。
5. 事务内查询同一场地、同一日期、`pending/confirmed` 状态的重叠预约。
6. 时间重叠条件为：`new_start < old_end AND new_end > old_start`。
7. 如果 MySQL 无冲突，则在同一事务内写入预约记录和费用快照并提交。
8. 如果发生冲突或写入失败，需要回滚事务并释放 Redis 锁。
9. 如果预约取消或超时，需要更新 MySQL 状态，并释放或等待 Redis key 过期。

说明：Redis 锁用于降低同一时间段的并发冲突概率，MySQL 事务是最终一致性保护。这样可以覆盖“09:00-11:00”和“10:00-12:00”这类起止时间不同但实际重叠的预约请求。

费用快照计算规则：

- `duration_minutes = end_time - start_time`
- `original_amount_cents = price_per_hour_cents * duration_minutes / 60`
- 当前阶段暂不接入真实优惠券和会员折扣，`discount_amount_cents = 0`
- `payable_amount_cents = original_amount_cents`

已有数据库升级到该结构时，执行 `scripts/upgrade_phase1_court_assets.sql`。该脚本通过 `information_schema` 判断字段是否存在，可重复执行，并会给现有场地和历史预约填充默认资产与金额快照。

## 7. 初始数据建议

系统初始化时建议写入：

- 一个管理员账号。
- 若干个测试场地。
- 默认系统配置。

示例配置：

```sql
INSERT INTO config (config_key, config_value, description, created_at, updated_at) VALUES
('max_reservation_hours', '2', '单次最大预约小时数', NOW(), NOW()),
('reservation_lock_ttl_seconds', '300', '预约锁超时时间，单位秒', NOW(), NOW()),
('advance_reservation_days', '7', '可提前预约天数', NOW(), NOW()),
('daily_reservation_limit', '3', '用户每日最大预约次数', NOW(), NOW());
```
