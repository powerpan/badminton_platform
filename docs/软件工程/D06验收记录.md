## 3. 20 并发 HTTP 性能

复现：[性能脚本](../../scripts/benchmark_staff_payments.py)。每类先执行 1 次首请求，再执行 200 次请求，并发上限 20；包含实际 HTTP 序列化、鉴权、数据库查询与事务。首请求不等同于清空 MySQL/操作系统缓存的冷启动，原始 JSON 中 `cold_ms` 指该组首个 HTTP 请求。

隔离样本为 20 个客户、1 种商品和 201 个通过业务服务创建的待付单；201 次收款分别处理不同订单。报价阶段仍有待付库存占用；财务查询阶段已生成 201 笔成功付款及取货凭证。

| 场景 | 首请求 | 并发 P95 | 最大值 | 失败/200 | 验收阈值 |

| 商城报价 | 2.62 ms | 17.93 ms | 21.31 ms | 0 | ≤ 2000 ms |
| 模拟收款 | 10.18 ms | 74.46 ms | 95.50 ms | 0 | ≤ 3000 ms |
| 管理员交易流水 | 71.58 ms | 349.48 ms | 462.51 ms | 0 | ≤ 2000 ms |

最终核对：成功付款 201，待取货码 201，库存 500→299，销量 201，有效待付占用 0，余额流水 0；渠道净收款 201000 分。达成本地样本目标，但没有覆盖大型历史库、外网延迟或持续营业负载。原始结果：[性能 JSON](验证结果/2026-09-24-性能.json)。

### 9.1 四尺寸与发现的布局问题
