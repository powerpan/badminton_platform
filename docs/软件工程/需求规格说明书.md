# 软件需求规格说明书

版本：SRS v1.0；日期：2026-09-23；关联：[文档索引](README.md)。

本文以现有项目为基础，细化已确认的前台收银与模拟支付需求。现有功能仅表示代码中存在，新增功能正在分批实施；验收结论见 [开发记录](开发进度与验证记录.md)，不能由本文推定。

## 1. 项目背景与范围

系统服务于单个羽毛球馆，统一线上预约、线下开场、会员储值、器材销售、赛事交流和运营管理。保留 Vue 3、Tornado、MySQL、Redis 架构，通过增量改造支撑前台设备收银和管理员全局追溯。

| 范围 | 内容 |
| --- | --- |
| 保留 | 注册登录、场地展示与预约推荐、连续选时、会员等级与积分、预约改期与到场记录、商城、赛事报名、公告、社区、通知、经营统计 |
| 新增或调整 | 四角色权限、散客整段开场与续场、内部模拟支付宝、商城待支付与取货码、前台代充值、全系统订场与流水查询、维修只读入口 |
| 网站链接 | 提供最终可访问的网站 URL，供后续微信公众号菜单或文章使用；本阶段不接入微信身份体系 |
| 不在本批 | 微信登录、小程序、真实支付宝/官方沙箱、用户自助充值、散客会员折扣、分批取货、维修接单完工流程、多门店、财务会计总账 |

此前暂缓的旧安全事项维持原有范围决定。本批需要实现自身角色权限、金额校验和幂等约束，不据此扩大为全仓库安全整改。

## 3. 角色权限矩阵

“本人”表示仅限自己的消费和账户；“工作范围”表示完成前台服务所需的场地、散客订单、充值及取货信息，不等于全局财务权限。匿名访客沿用当前公开浏览能力。

| 操作 | 普通用户 | 前台 | 管理员 | 维修人员 |
| --- | --- | --- | --- | --- |
| 浏览公开场馆、公告、商品、赛事 | 可 | 可 | 可 | 可 |
| 线上预约、会员消费与本人订单 | 本人 | 不使用此入口代客消费 | 沿用现有入口 | 不开放消费入口 |
| 场地排期与散客开场/续场 | 否 | 工作范围 | 可 | 仅维修安排 |
| 前台设备模拟收款、取消散客未付单 | 否 | 工作范围 | 可 | 否 |
| 查询会员用于代充值 | 本人资料 | 最小识别信息与充值所需余额 | 全部 | 否 |
| 正金额代充值 | 否 | 可 | 可 | 否 |
| 余额增减、积分或等级人工调整 | 否 | 否 | 可 | 否 |
| 查看商城取货码 | 本人已付订单 | 按码查待交付订单 | 可 | 否 |
| 确认商品核销 | 否 | 可 | 可 | 否 |
| 申请商城退款 | 本人且符合原条件 | 否 | 可处理 | 否 |
| 工作台已付款退款处理 | 否 | 否 | 可，受订单条件约束 | 否 |
| 线上预约取消/改期 | 本人且符合原条件 | 不代办会员改期 | 沿用管理能力 | 否 |
| 赛事、公告、社区管理与发布 | 社区本人动态；赛事报名 | 否 | 可 | 否 |
| 维修登记、释放场地 | 否 | 否 | 可 | 否 |
| 全局订场、流水、经营统计、日志 | 否 | 否 | 可 | 否 |
| 用户角色、价格、规则配置 | 否 | 否 | 可 | 否 |

前台可以查看同一球馆散客工作单并接续处理，日志记录每次实际经办人；该数据范围为第一版工作台设计约定。原线上会员自助取消规则保留：不能将“前台无已付退款权限”误实现为取消普通用户现有合法操作。新增退款处理权限不放宽原订单的退款条件。

## 4. 功能需求

| 编号 | 需求与完成标准 |
| --- | --- |
| FR-01 | 网站链接：提供部署后的 HTTPS 访问入口和微信内打开说明；手机可浏览、登录、预约与查单；未部署时不虚构公网地址 |
| FR-02 | 四角色：登录后进入对应工作区；菜单、路由和后端接口一致限制权限；禁用或角色变更在后续请求中生效；公开注册不能自选工作人员角色 |
| FR-03 | 散客开场：前台在当前空闲段开始接待，可连选后续空闲整段；无需客户账户，姓名和联系方式选填；保留场地、金额、来源、客户标识和经办人 |
| FR-04 | 预付占场：创建订单临时占用，成功收款才正式开场；取消、超时、无效时段释放；线上、散客、改期与维护共享防冲突边界 |
| FR-05 | 续场：对后续相邻空闲整段新建关联订单，原价另付；失败不改变原场次，提前离场不自动退款，结束后自动结束 |
| FR-06 | 双渠道支付：线上订场与商城可选余额或内部模拟支付宝；前台开场在工作人员设备模拟收款，不扣前台余额、不转交客户账户 |
| FR-07 | 会员与核价：线上订场两渠道享相同折扣和积分；散客原价且无积分；商城无新增会员折扣；确认和提交校验最新报价 |
| FR-08 | 取消与退款：未付取消释放资源；已付按允许的角色和既有业务条件处理；退回原渠道，禁止重复退款或越过已取货限制 |
| FR-09 | 预约改期：保留原功能，按原支付渠道处理补差/退差；新场次锁定及结算成功前保留原预约；变更历史可追溯 |
| FR-10 | 商城取货：成功支付后生成整单取货码；工作人员先查单核对再确认；未付、退款中、已退款或已核销不能核销；退款驳回可恢复取货 |
| FR-11 | 前台代充值：确认已有会员与正金额后，在前台设备模拟收款，成功后入账一次；记录目标会员、经办人、前后余额；不修改积分、等级 |
| FR-12 | 全部订场查询：管理员按日期、场地、来源、状态、渠道、客户、经办人分页筛选，查询线上、散客与续场及其支付、退款、改期关联详情 |
| FR-13 | 全局流水查询：管理员查看订场、商城、续场、充值、人工调整、退款、改期差额；支持类型、渠道、时间、状态、客户、经办人和业务单筛选 |
| FR-14 | 统计：分别展示消费结算、渠道收退款、储值充值、余额消费和人工调整；充值后余额消费不计作第二次渠道收款；区分计费占用和实际到场 |
| FR-15 | 维修查看：维修人员仅查看被管理员明确归类为维修的场地、时段、原因与安排状态；包场不冒充维修；维修人员不能恢复开放 |
| FR-16 | 兼容与回归：旧订单、余额、积分、商品、内容、推荐、报名等仍可用；缺失历史依据显示未记录；提供增量升级和验收证据 |

## 5. 核心用例

| 用例 | 前置条件 | 主流程 | 异常与终点 |
| --- | --- | --- | --- |
| UC-01 散客开场 | 前台有效；当天当前时段空闲 | 选择场地与完整段 → 最新报价 → 确认创建 → 设备收款 → 开场凭证 | 价格变化重新确认；冲突不建有效占用；未付只临时占场 |
| UC-02 散客续场 | 存在可续的原散客场次 | 查看后续空段 → 确认整段原价 → 新单收款 → 关联原单 | 下一场已占不能续；支付失败不延长使用截止时间 |
| UC-03 线上消费 | 普通用户有效；场次或库存有效 | 选择渠道 → 核价 → 创建待付单 → 支付 → 查单 | 模拟渠道不检查余额是否够用；超时订单需重新下单 |
| UC-04 商品取货 | 商城已付、无退款处理中 | 用户出示码 → 工作人员查询 → 核对商品与数量 → 确认 → 完成 | 查询不核销；重复确认返回原核销结果；其他状态拒绝 |
| UC-05 会员充值 | 已识别目标会员；金额大于零 | 确认客户与金额 → 建充值单 → 前台收款 → 入会员余额 | 取消不入账；目标不明不能提交；网络重试先查询原单 |
| UC-06 管理员追溯 | 管理员有效 | 筛选订场/流水 → 看业务详情 → 查支付、退款、账户、经办链 | 空数据明确展示；历史缺项不能补造付款或到场事实 |
| UC-07 维修查看 | 维修角色有效 | 登录维修区 → 按日期/场地/状态筛选 → 看原因和安排 | 无维修时显示空状态；直接调用写接口同样拒绝 |

## 6. 金额、时间和状态规则

- 金额使用整数分。现有按小时价格按完整配置时段换算；例如 120 元/小时、60 分钟段，14:10 到店选择 14:00–15:00，应付 120 元、15:00 结束。30 分钟配置则按完整半小时段计费。
- 时段为半开区间 `[开始, 结束)`，14:00–15:00 与 15:00–16:00 相邻不冲突。不能补开已经结束的段，不能跨非空段连选。
- 时间由服务器判定，浏览器倒计时仅作提示。当前段结束时不可再支付包含该过期段的开场订单，具体多段截止约定见系统设计。
- 会员权益沿用预约日期对应的有效等级与既有计价/积分规则；已经创建的有效订单保留金额快照，后台调价不追改该单。
- 商城订单创建前按逐项商品单价核对；待付单创建后固定价格和数量，在有效期内支付该快照金额。
- 散客计费开始时间不代表实际到场时间；续场关联链不能重复计为新到店人数。预约到场与商城核销分别记录。
- 状态转移和各渠道金额影响见 [系统设计](系统设计说明书.md)；接口路径、超时配置和表名是设计，不是客户额外确认过的需求。

## 7. 非功能需求

| 编号 | 可验证要求 |
| --- | --- |
| NFR-01 权限与归属 | 每个写接口校验角色、订单归属和业务状态；前台/维修不能通过直接 HTTP 请求绕过菜单限制 |
| NFR-02 一致性 | 同一场次并发只有一个有效占用；同一支付、充值、退款或核销重复处理不产生第二次业务效果；失败整体回滚 |
| NFR-03 可恢复 | 刷新、断网重试、服务重启后可查原订单；过期任务停止期间，请求入口仍拒绝过期支付并最终释放资源 |
| NFR-04 易用性 | 前台先见排期和待收款，维修先见任务；360/390/768/1440px 检查，键盘焦点清晰，避免输入多重框和页面横溢 |
| NFR-05 性能 | 验收目标：约定的本地隔离环境、20 并发操作下列表/报价 P95 ≤ 2 秒，内部模拟收款 P95 ≤ 3 秒；代表性场景已测量，环境、样本量与限制见 D06 验收记录 |
| NFR-06 可追溯 | 管理员能由业务单查到渠道、状态、金额、经办、账户变动与退款；新增成功资金事务必须同事务记录审计依据 |
| NFR-07 可迁移 | 新库初始化与旧库升级结构一致；迁移可重复检查，历史行数/余额/积分守恒，未知信息明确标识 |
| NFR-08 可维护 | 沿用分层与公共规则，迁移、接口、测试与文档同步；模拟支付标识始终可见，不要求真实支付配置 |

性能阈值是本批工程验收目标；代表性本地样本已有测量结果，见 [D06 验收记录](D06验收记录.md)。这些数据不代表外网响应或真实营业容量承诺。用例覆盖与交付门槛见 [测试与验收计划](测试与验收计划.md)。
