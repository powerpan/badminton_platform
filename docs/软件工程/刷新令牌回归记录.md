# 刷新令牌核查与回归

日期：2026-11-10。核查基线：`38e0d32`。状态：历史缺陷已核实，前端遗漏已修复，专项与完整回归通过；用户已确认将本轮代码、测试和文档提交并推送到仓库。

## 核查结论与本次范围

历史问题属实。`2e45945` 中的 `decode_refresh_token()` 调用 `decode_access_token()`，后者不接受 `token_type=refresh`，因此正常刷新令牌也会被拒绝。`38e0d32` 已将签名、有效期检查提取为 `_decode_token()`，访问和刷新令牌分别校验类型；此前手机扫码变更记录写的是已经修复的问题。

现有测试覆盖基本类型分离及手机会话续期，但缺少独立的 HTTP 刷新契约和过期回归。本次补齐真实 Tornado HTTP、JWT 与临时 Redis 检查，用户读取使用夹具。测试禁止连接 MySQL，使用自建 Redis，不操作正在使用的登录会话。后端解码修复已经存在，无需重复修改。

前端遗漏也已复现：`/auth/profile` 的 401 被整个 `/auth/` 路径排除条件拦住，刷新令牌仍有效时也会清理会话并转登录。修改 [http.ts](../../frontend/src/api/http.ts) 的判断，只有登录、注册、刷新等公共认证接口不触发自动续期；受保护的资料和改密请求可以刷新一次后重试。

先补 [前端回归](../../frontend/tests/authSession.test.mjs)：修复前 9 项中 1 项失败，原因是资料请求没有发起刷新；修改后 9 项全部通过。[后端专项](../../backend/tests/test_auth_refresh.py) 新增 13 项测试。历史对照使用 `git show 2e45945:backend/utils/tokens.py` 在独立命名空间加载旧代码，对同一有效刷新令牌，旧版返回 401，当前版正确解码为 refresh。
