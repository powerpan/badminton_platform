# 测试与验收计划

版本：STP v1.0；日期：2026-09-23；状态：本地执行完成；设备/登录与部署缺项见逐条结果。[文档索引](README.md)。

目标是验证 [需求规格](需求规格说明书.md) 和 [系统设计](系统设计说明书.md)，尤其是角色隔离、整段收费、渠道收退款、充值与核销的一次性效果。本文件是计划，不是测试报告。

本计划保留 42 条用例定义；实际状态见 [D06 用例追踪](D06用例追踪.md)：38 条本地通过、3 条部分通过、1 条因正式部署/设备条件未执行。不将局部验证升级为整条用例通过。

## 1. 测试范围与环境

- 单元层：计价、时间边界、角色规则、可用余额、统计分类、请求摘要与状态转移。
- 集成层：MySQL 真实事务、Redis 占用、并发、异常回滚、升级兼容；使用独立数据库和独立 Redis 实例/命名空间。
- API 层：四角色和匿名请求，覆盖合法、非法、越权和幂等重试。
- 页面层：桌面 1440×1000、平板 768×1000、手机 390×844 与 360px 宽；正常操作、空数据、错误、键盘、刷新恢复。
- 交付层：迁移演练、备份恢复、入口链接、微信内浏览器实机检查；未执行的设备和场景明确标未测。

测试数据显式标记“演示/测试”，不对现有业务库下单、付款、充值、退款或修改库存。四种角色使用隔离测试账号，凭据不写入报告或仓库。固定服务器时钟测试 14:10/14:59:59/15:00，不能靠等待真实时间重现边界。

样例：场地 A 单价 12000 分/小时，B 单价 10000 分/小时；60 分钟与 30 分钟两套时段；普通及有效/过期会员；余额 0、10000、足额三类账户；商品库存 0、1、多件；含未知支付依据、未分类维护和未记录到场的旧数据。

## 4. 数据断言与测试依据

支付前后必须核对业务单数量与状态、支付成功次数、余额/积分及其流水、商品库存/销量/占用、取货凭证、退款和操作日志。建议保存以下断言的实际值：

- 客户期末余额 = 期初余额 + 该客户账户流水余额变化总和；积分同理。
- 一笔支付累计成功退款 ≤ 成功支付金额；最终取消的可退款业务净额归零。
- 充值成功数量 = 对应充值入账效果数量；失败或过期充值的余额变化为零。
- 商品可售库存 = 未售库存 − 有效待付占用，且不小于零；库存基数、人工调整、支付扣减与退款恢复可以勾稽。
- 查询日期内成功收款减退款等于对应渠道净额；不把订单快照与其账户流水重复加总。
- 同一场地有效区间无重叠；到场统计不把续场子单或时间已结束当作新到场事实。

并发至少使用两个独立数据库连接，设置同时提交屏障；失败注入位于事务中间。调用 mock 函数的单元测试不能替代这些事务断言。
