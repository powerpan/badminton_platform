# 角色操作手册

版本：MANUAL v1.0；日期：2026-09-23；状态：四角色、散客开场/收款/续场、线上订场/商城双渠道及取货已实现；代充值、全部订场筛选、交易流水与分类汇总也已实现，验证范围见开发记录。[文档索引](README.md)。

当前可用：管理员创建/分配四角色及维护分类；前台在“前台工作台”选择“开场收款”，核价后创建待收款单；在“散客工作单”模拟付款、撤销未付单和续场；维修安排按日期、场地、状态查询。普通用户可在预约与商城选择两种渠道；前台“商品取货”可查码核销。前台“会员储值”可精确查询客户、办理模拟收款和查询本人工作单；管理员“会员储值”可查全部。管理员“预约管理”和“交易流水”已提供全量分页筛选、关联凭据与分类汇总。

本手册用于分批开发和演示验收，其余菜单名称为设计名称。实施后应补充真实页面截图并复核步骤；当前运行方法仍按 [部署说明](../部署说明.md)。

## 1. 普通用户

### 订场与商城支付

1. 登录后选择场地日期、连续时间段，或将商品加入购物车。
2. 在结算中选择“储值余额”或“模拟支付宝”，检查最新金额、会员优惠、商品数量和时间。
3. 确认创建订单后，在截止时间前付款。已创建订单保持其报价，逾期需重新下单。
4. 余额付款从本人的储值账户扣款；模拟支付宝显示项目内模拟支付页，确认成功后可回订单查询。模拟操作不发生真实扣款。
5. 支付后查看预约凭证或商城取货码；付款完成但页面刷新失败时先查原订单，不重复创建新单。

线上订场的会员折扣和积分不因支付渠道改变，商城第一版不新增会员折扣。预约改期仍需重新确认目标场次和差额；改期成功前原场次保留。模拟补差确认时目标已被占用，会提示重新选场且不收取差额。

### 商城取货与取消

打开本人已付款订单，向前台出示取货二维码或可读码；由工作人员核对商品后确认领取。码用于取货，不是支付码。退款申请中不能取货，已核销不能再次领取。

未付订单可取消；已付商城订单按原规则申请退款，由管理员处理。本人线上预约取消沿用原条件。退款返回原付款渠道，模拟支付退款不会变成储值余额。

## 2. 前台人员

### 散客到店开场

1. 打开“前台工作台”的“场地排期”，查看当日场地排期与当前空闲段，点击“开场收款”。
2. 选择场地和当前完整时间段，需要时连续选择后续空闲段；姓名、联系方式可选填，不要求散客注册。
3. 向客户确认计费段、原价及结束时间。例如 14:10 到店选择 14:00–15:00，收整段价格，使用到 15:00。
4. 点击“核对金额”，再“确认金额，创建待收款单”，这一步只临时占场。在前台设备点击“模拟付款成功”并确认金额，核实成功后才正式开场。
5. 检查支付成功凭证和使用截止时间。订单会记录实际经办人，不扣前台个人余额。

时间段或价格变动时重新确认，不能沿用旧页面金额。错选未付单可取消重开，支付已成功则不能从前台退款入口处理，应交管理员按订单条件办理。

### 续场

从原散客订单进入续场，查看后续相邻段是否空闲，确认原价并另行收款。只有续场单付款成功才获得新增时间；不能覆盖下一位客户的预约。提前离场不会自动退费。

### 帮助会员储值

打开“前台工作台 → 会员储值”，输入完整用户名或登记联系方式精确查询，再点击“选择客户”。核对用户名、昵称和脱敏联系方式，输入正数金额（元，最多两位小数），点击“确认客户与金额”。创建后在充值单中点击“前往模拟收款”，确认目标账户后点击“模拟付款成功”；随后核对凭证中的入账前/后余额和实际收款经办人。模拟失败、撤销或超时均不增加余额。

前台的“我的充值工作单”只列本人开单记录；管理员“会员储值”可看所有充值单并继续办理。支持日期、状态、完整充值/收款单号筛选及分页。关闭页面后从原单继续收款，开单结果不确定则恢复原请求。客户在会员中心“柜台储值”分类查看入账，点击到账通知也可进入会员中心。

前台不能以负数充值抵扣余额，也不能借充值修改会员等级、积分。若充值对象或金额有误且已经成功，保留单号交管理员核查，不通过再次充值进行冲抵。

### 商品取货

打开“前台工作台 → 商品取货”，输入客户的 12 位可读码或扫码得到的 `BF-PICKUP:` 内容，点击“查询取货单”。先核对商品名称、数量和订单状态，再点击“确认整单交付”并确认。当前已验证键盘输入，未提供浏览器摄像头扫码入口；真实扫码枪/手机识别待设备验收。只打开码的查询结果不会完成取货；重复确认应显示原核销人和时间，不重复发货。

前台不具备赛事、公告、社区发布、商品调价、全局财务与会员等级管理权限。工作台按实际接待任务设计，不需要切到客户账户收款。

## 3. 管理员

### 管理与内容

管理员保留场地、用户、会员、商品、赛事、公告、社区、规则与日志等功能。为工作人员分配“前台”或“维修”角色；公开注册不提供工作人员选项。

登记场地封锁时明确选择维修或包场，填写时间和原因；不能静默覆盖已有预约。旧封锁显示未分类，需要确认类别后才能成为维修人员的任务。恢复开放由管理员操作。

### 查看全部订场（已实现）

进入后台“预约管理”，按场次日期、场地、来源、状态、支付渠道、客户或开单经办组合筛选。客户可输入账号、昵称、登记联系方式或散客信息；完整单号支持预约号、订单号、支付号和退款号。查询后按页浏览；手机显示订场卡片。

打开详情查看原场次与全部续场，包括取消的子单；点击“查看该场次”切换关联记录。收款记录分别显示开单人与成功收款经办，退款列明对应原支付单、渠道及退回金额，下方可查看账户余额/积分变动和改期记录。没有统一支付单的旧记录会提示核查原账户流水，不把“已结束”认定为付款或到场。

### 交易流水与分类汇总（已实现）

在“交易流水”按时间、业务类型、渠道和状态筛选，查看订场、商城、充值、退款、人工调整与改期差额，并追溯对应业务单和账户记录。资金列表发生时间与场次日期分开，跨日查账应按实际收退款时间选择范围。

例如客户先模拟充值 100 元、再用余额消费 100 元，渠道收款仍为 100 元；余额消费另列 100 元，不能将两者当成 200 元渠道收款。余额退款只计入“退回余额”和消费退款，不抵减模拟渠道收款。人工调增、调减单列，不作为经营收入。

默认查询最近 30 天，单次最多 366 天；展开“更多筛选”可按客户、经办人或完整业务/支付/退款单号查找。成功收退款按实际经办人查询，尚未收款的单据按开单人查询。更改条件后点“查询流水”才生效；翻页保留上次提交的条件，汇总始终包含全部匹配记录。

点击“凭据”查看业务单、原支付、退款、余额及积分记录；订场凭据可进入预约与续场详情。“账户核对”检查本次记录涉及客户的完整账户流水与当前余额、积分，不只核对当前页或日期范围。初始余额沿用第一笔历史记录，不能据此证明外部资金已到账；无记录或不一致时按原始凭据核查，不能直接改账抹平。标为历史待核对的订单不作为已有付款证据。

### 退款与账户调整

处理退款前核对业务类型、原支付渠道、退款资格和取货状态，确认后查看退款结果。余额退回余额，模拟渠道产生模拟退款记录。已取货商品不能用普通订单退款入口重复退款。

管理员人工余额/积分调整需记录原因，与前台实际模拟收款后的充值分开。人工调整本身不等于渠道收到款项。

## 4. 维修人员

登录后查看“维修安排”，按日期、场地和状态查阅需要维修的场地、时段与原因。第一版仅查看；不能新建任务、接单、标记完工或恢复场地，也不能访问客户资料、商城或资金记录。

维修结束后的恢复开放由管理员办理。没有安排时页面显示“暂无维修安排”，不能把包场或未分类旧记录解释成维修任务。

## 5. 常见异常处理

| 提示或情况 | 正确处理 |
| --- | --- |
| 价格已变化 | 重新核价，向客户确认新金额后提交 |
| 场次已被占用 | 刷新排期，另选空场；原改期场次仍保留 |
| 收款超时 | 原单不可继续付款，按当前可用时间段重新开单 |
| 网络中断，不确定付款结果 | 查询原单号；成功则不重复付款，待付才按页面提示重试 |
| 取货码无效或已使用 | 核对订单状态和原核销记录，不重复交付 |
| 余额不足但客户希望模拟付款 | 新建单时选择模拟支付宝；已有余额待付单先取消再重建，场次/库存会重新检查 |
| 前台无法退款或修改会员权益 | 由管理员检查相应业务，保留单号和原因 |
| 历史付款或到场未记录 | 展示未记录状态，不人工猜测并补成成功 |
