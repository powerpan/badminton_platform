# 手机扫码登录与取货变更

日期：2026-11-10。状态：已实现，本地自动化与浏览器验收通过，用户试用后同意提交到仓库；正式部署及具体设备验收另行记录。关联需求 FR-17。

## 使用流程

普通用户在电脑完成商城付款后进入该单取货凭证页，并弹出“在手机查看”二维码。手机扫码后显示账号及六位核对码；电脑显示相同核对码，用户点击“允许此手机登录”后，手机获得独立登录状态，自动进入该单凭证页，截图后到馆领取。手机布局付款后直接展示凭证。已有订单也可重新发起手机查看。

本次授权是完整普通用户登录，包含余额消费等正常账号权限。管理员、前台、维修账号不开放这个入口。手机已有不同账号时，必须明确同意切换才兑换登录；不悄悄覆盖原会话。授权只在扫码打开的浏览器中生效。

## 授权与失效规则

- 二维码只包含随机请求编号及临时扫描票据，放在 URL fragment，页面读取后清除；不放账号访问令牌、刷新令牌或取货码。
- 请求有效期 120 秒，二维码只允许一台手机绑定。手机生成独立随机设备密钥；后端只保存摘要，确认和兑换绑定同一设备。核对码是人工比对信息，不是兑换密钥。
- 发起、查询、允许和拒绝必须由创建请求的电脑登录会话操作。允许时提交当前核对码。关闭弹窗、刷新二维码、用户拒绝均取消未兑换授权；页面异常关闭时由 TTL 兜底。
- 兑换前复核普通用户角色、启用状态、密码未变化及本人订单仍为待取货。二维码到期、拒绝、取消、错误设备或订单状态变化均不能登录。
- 一次授权只签发一套手机令牌。为处理响应丢失，仅允许同一设备在首次兑换后的短窗口内取回同一结果，不新增会话；窗口结束须重新扫码。电脑会话不会被复制给手机。
- 手机登录与取货核销分开。登录二维码过期不影响已保存的取货凭证；退款冻结、退款失效和一次性整单核销继续由原业务接口校验。
- 新增手机入口使用配置项 `MOBILE_WEB_ORIGIN`，正式环境必须为 HTTPS；开发环境可配置手机能访问的局域网 HTTP 地址。不能使用 localhost/127.0.0.1；不根据请求 Host 拼接授权链接。未配置时保留原取货方式并给出提示。
- 接口响应 no-store，敏感参数使用 POST 请求体；对发起与手机匿名接口限速。临时票据、设备密钥及令牌不写操作日志。

## 实现范围

复用 Vue、Tornado、Redis、账号令牌和商城凭证接口。增加跨设备授权服务/路由、电脑授权弹窗、手机接收页及可直接访问的单笔取货页。Redis 保存短期状态，不增加 MySQL 表，不修改订单金额、库存或核销规则。

修复现有刷新令牌解码误用访问令牌校验的问题，增加类型隔离测试，使手机独立会话可正常续期。支付成功后的跳转仅针对商城。

## 状态与接口

状态：`waiting → claimed → approved → issuing → consumed`；允许拒绝/取消到 `denied`，失败到 `failed`，TTL 到期视为 `expired`。并发状态转换使用 Redis 原子比较更新。消费回执最多保留 30 秒，且不延长原请求有效期。

| 接口 | 身份与行为 |
| --- | --- |
| POST `/api/auth/mobile-handoffs` | 普通用户；本人待取货订单；返回 id、二维码和有效期 |
| GET `/api/auth/mobile-handoffs/{id}` | 创建电脑会话；查询状态/核对码，不返回手机令牌 |
| POST `/api/auth/mobile-handoffs/{id}/decision` | 创建电脑会话；允许、拒绝或取消；允许需匹配核对码 |
| POST `/api/auth/mobile-handoffs/{id}/claim` | 扫描票据 + 手机设备密钥；绑定首次申请设备并返回账号/核对码 |
| POST `/api/auth/mobile-handoffs/{id}/exchange` | 绑定设备密钥；等待授权或取回一次签发的登录结果及固定订单目标 |

实际页面操作：电脑余额付款 → 自动弹码 → 手机显示相同核对码 → 电脑允许 → 手机自动进入对应订单 → 截图凭证 → 前台查询并确认交付 → 手机显示已领取。另验证手机已登录其他账号时必须确认切换、取消后仍为原账号、拒绝后停止等待，以及手机直接模拟支付宝付款后展示凭证而不弹电脑授权。

QR-01–QR-07、QR-14 的后端约束有自动化覆盖；QR-08、QR-09、QR-12、QR-13 通过页面及隔离库验证；QR-10 使用组件生命周期测试与取消竞争测试覆盖，QR-11 使用二维码解码和页面 URL 核查。核销/退款并发和重复请求由既有隔离库集成回归覆盖。网络故障覆盖了异步模拟、签发异常与同设备丢响应重试，没有做物理断网试验。

本轮修复了现有刷新令牌被误当访问令牌拒绝的问题，并为每次签发的访问令牌加入独立标识。前端另防止账号切换前的迟到 401、刷新响应和资料响应覆盖新会话。拒绝授权后明确显示结束状态。测试时发现开发服务器文件监听未更新模块，已重启并核对实际返回的源码后复测，未将旧页面结果作为最终版本证据。

## 启用与现场验收

在后端环境配置 `MOBILE_WEB_ORIGIN` 为手机可访问的前端源站，例如开发时 `http://192.168.1.10:5188`（替换为实际局域网地址），正式环境填 `https://实际域名`，不带路径、查询参数或账号信息。重启后端并更新前端；代理需支持 `/mobile-handoff/{id}` 与 `/shop/orders/{id}/pickup` 的前端路由刷新。配置只决定链接目标，不增加服务器监听或公网暴露。

未配置时正常取货凭证仍可查看，手机扫码入口提示尚未开通。不能把 `localhost` 用作手机入口。正式 HTTP 地址会被拒绝。

待现场验收：真实手机相机/微信内浏览器识码、浏览器之间的登录隔离、正式 HTTPS 与反向代理、真实扫码枪。当前二维码解码和两个浏览器来源的闭环验证，不等于这些设备已经验收。登录会话沿用现有退出规则：退出撤销对应刷新会话，已签发访问令牌到期前的行为沿用原系统，不扩展为全站会话管理改造。
