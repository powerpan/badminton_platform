## 文档控制

- 需求编号 `FR-01` 至 `FR-16`、非功能编号 `NFR-01` 至 `NFR-08` 保持稳定，修改文字不随意重排编号。
- 每项需求在测试计划中有对应 `TC-xx`，实施任务使用 `D01` 至 `D06`；实现时登记提交、接口、迁移脚本和测试证据。
- 已确认业务规则以用户确认和需求确认文档为依据；表名、路由、超时细节等属于设计约定，实施中可在不改变业务规则的前提下同步调整。
- 新增设计与代码不一致时，保留“待实现”标记；完成代码后更新实际文件、迁移版本与测试结果，再改为“已验收”。
- 数据库变更、测试交易、服务发布和 Git 推送按环境分别记录；隔离库验证不代表业务环境已升级。
