# 当前实现状态与下一阶段计划

## 1. 当前代码状态

截至当前阶段，项目已经完成从任务书到可运行业务版本的第二轮落地。当前版本包含用户认证闭环、场地预约闭环、后台基础管理和规则配置。

已完成内容：

- 后端 Tornado 应用入口、路由和统一 JSON 响应。
- MySQL 连接池、基础查询封装和核心 repository。
- Redis、MySQL、API 健康检查。
- 用户注册、登录、JWT 鉴权。
- 当前用户信息查询、资料修改和密码修改。
- 场地列表和后台场地维护。
- 按配置生成场地时间段，支持 `available/reserved/locked/disabled` 状态。
- 预约创建，使用 Redis `SET NX EX` 做并发窗口锁。
- MySQL 时间重叠冲突校验，最终防止重复预约。
- 我的预约列表和未开始预约取消。
- 管理员用户新增、启用/禁用、角色修改。
- 管理员预约列表、详情和取消预约。
- 管理员公告发布、编辑、显示/隐藏。
- 管理员规则配置查询和更新。
- Vue3 前端基础布局、路由、Pinia 登录态和 Axios 拦截器。
- 登录页、注册页、个人中心页、场地预约页、我的预约页、后台管理页。
- 前端路由守卫：未登录不能访问业务页，普通用户不能访问后台。
- 初始化 SQL、默认场地、默认配置和默认管理员账号。

默认管理员账号：

```text
username: admin
password: admin123456
```

说明：默认管理员只用于本地开发和演示，正式环境需要修改密码和 JWT 密钥。

## 2. 当前可用接口

### 2.1 健康检查

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/health` | 检查 API、MySQL、Redis 状态 | 无需登录 |
| GET | `/api/admin/health` | 管理员健康检查 | 管理员 |

### 2.2 认证接口

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | 注册普通用户 | 无需登录 |
| POST | `/api/auth/login` | 登录并返回 JWT | 无需登录 |
| GET | `/api/auth/profile` | 获取当前用户资料 | 登录用户 |
| PUT | `/api/auth/profile` | 修改昵称和联系方式 | 登录用户 |
| PUT | `/api/auth/password` | 修改密码 | 登录用户 |

### 2.3 用户端业务接口

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/announcements` | 查询显示中的公告 | 无需登录 |
| GET | `/api/announcements/{id}` | 查询公告详情 | 无需登录 |
| GET | `/api/courts` | 查询启用场地 | 登录用户 |
| GET | `/api/courts/{court_id}/slots?date=YYYY-MM-DD` | 查询场地时间段 | 登录用户 |
| POST | `/api/reservations` | 创建预约 | 登录用户 |
| GET | `/api/reservations/my` | 查询我的预约 | 登录用户 |
| PUT | `/api/reservations/{id}/cancel` | 取消我的预约 | 登录用户 |

### 2.4 管理员接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/admin/users` | 用户列表和新增用户 |
| PUT | `/api/admin/users/{id}/status` | 启用或禁用用户 |
| PUT | `/api/admin/users/{id}/role` | 修改用户角色 |
| GET/POST | `/api/admin/courts` | 场地列表和新增场地 |
| PUT | `/api/admin/courts/{id}` | 编辑场地 |
| PUT | `/api/admin/courts/{id}/status` | 启用或停用场地 |
| GET | `/api/admin/reservations` | 查询全部预约 |
| GET | `/api/admin/reservations/{id}` | 查询预约详情 |
| PUT | `/api/admin/reservations/{id}/cancel` | 管理员取消预约 |
| GET/POST | `/api/admin/announcements` | 公告列表和发布公告 |
| PUT | `/api/admin/announcements/{id}` | 编辑公告 |
| PUT | `/api/admin/announcements/{id}/status` | 显示或隐藏公告 |
| GET | `/api/admin/configs` | 查询规则配置 |
| PUT | `/api/admin/configs/{config_key}` | 更新规则配置 |

## 5. 下一阶段建议推送内容

下一阶段建议推送“统计分析与运维质量增强”。当前核心业务已经能跑通，下一阶段应提升展示效果、验收证据和系统可维护性。

建议包含以下内容：

1. 后台统计接口：预约总量、今日预约量、活跃用户数、场地使用率。
2. 统计图表页面：按场地、日期、时间段展示预约分布。
3. 操作日志写入：记录管理员用户、场地、预约、公告、配置操作。
4. 操作日志查询页面：支持按模块、操作者、时间筛选。
5. 预约自动状态处理：过期预约、已完成预约的定时或启动时修正。
6. 后端自动化接口测试：覆盖认证、预约、后台权限和规则配置。
7. 本地一键启动和演示检查脚本：降低演示前准备成本。
8. Docker Compose：统一 MySQL、Redis、后端、前端的演示环境。

完成后应达到：

- 管理员可以直观看到场馆运营情况。
- 管理员关键操作有记录可追溯。
- 预约状态不会长期停留在不符合时间条件的状态。
- 核心接口有自动化回归保障。
- 演示环境可以稳定、快速启动。

## 6. 下一阶段暂不建议优先做的内容

以下内容可以继续后置：

- 支付。
- 短信验证码。
- 会员等级。
- 积分。
- 复杂排班。
- 小程序端。

原因是这些扩展会增加业务复杂度。当前项目更需要先把统计、日志、测试和部署补齐，这些内容更直接支撑课程验收和演示。
