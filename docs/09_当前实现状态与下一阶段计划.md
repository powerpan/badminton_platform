
说明：默认管理员只用于本地开发和演示，正式环境需要修改密码和 JWT 密钥。

## 2. 当前可用接口

### 2.1 健康检查

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/health` | 检查 API、MySQL、Redis 状态 | 无需登录 |
| GET | `/api/admin/health` | 管理员健康检查 | 管理员 |

### 2.2 认证接口

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | 注册普通用户 | 无需登录 |
| POST | `/api/auth/login` | 登录并返回 JWT | 无需登录 |
| GET | `/api/auth/profile` | 获取当前用户资料 | 登录用户 |
| PUT | `/api/auth/profile` | 修改昵称和联系方式 | 登录用户 |
| PUT | `/api/auth/password` | 修改密码 | 登录用户 |

## 4. 已验证内容

已完成的验证包括：

- `npm run build` 构建通过。
- 后端 Python 编译通过。
- `/api/health` 返回 API、MySQL、Redis 均为 `ok`。
- `/api/auth/register` 可以注册普通用户。
- 重复用户名注册返回 `409`。
- 管理员账号可以登录。
- 错误密码登录失败。
- 无 token 访问个人资料返回 `401`。
- 普通用户访问 `/api/admin/health` 返回 `403`。
- 修改个人资料成功。
- 旧密码错误时不能修改密码。
- 正确旧密码可以修改密码。
- 未登录访问 `/courts` 会跳转 `/login?redirect=/courts`。
- 管理员登录后可以访问 `/admin`。
- 普通用户访问 `/admin` 会被拦截回首页。

## 5. 下一阶段建议推送内容

下一阶段建议推送“场地与预约基础闭环”。这部分是任务书中最核心的业务能力，应优先于统计、公告和复杂后台功能。

建议包含以下内容：

1. 场地列表接口和页面接入。
2. 场地时间段状态查询。
3. 预约创建接口。
4. Redis 预约锁。
5. MySQL 预约冲突校验。
6. 我的预约列表。
7. 取消预约。
8. 对应的接口冒烟测试和前端页面验证。

完成后应达到：

- 普通用户登录后可以看到真实场地。
- 用户可以按日期查看某个场地的时间段状态。
- 用户可以提交预约。
- 同一场地同一日期同一时间段不能重复预约。
- 用户可以查看自己的预约。
- 用户可以取消自己的有效预约。

## 6. 下一阶段不建议优先做的内容

以下内容可以放到“场地与预约闭环”之后：

- 管理员用户管理完整页面。
- 公告管理。
- 统计分析图表。
- 系统配置页面。
- Docker 部署。
- 支付、短信、会员、积分等扩展功能。

原因是这些功能依赖核心预约数据。先完成预约闭环，后续后台和统计才有真实数据可以展示。
