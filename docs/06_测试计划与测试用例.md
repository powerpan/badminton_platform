# 测试计划与测试用例

## 1. 测试目标

本测试计划用于验证 BF羽毛球馆管理平台是否满足任务书和需求规格说明书中的功能要求。测试重点包括用户注册登录、验证码、找回密码、会员账户、场地查询、在线预约、Redis 防重复预约、预约扣款退款、管理员后台管理、统计分析、系统规则配置和健康检查。

## 2. 测试范围

### 2.1 功能测试

- 用户注册。
- 用户登录。
- 图形验证码。
- 找回密码。
- 个人信息管理。
- 会员账户展示、等级折扣、余额和积分变化。
- 场地浏览。
- 时间段查询。
- 创建预约。
- 取消预约。
- 公告浏览。
- 管理员用户管理。
- 管理员场地管理。
- 管理员预约管理。
- 管理员公告管理。
- 统计分析。
- 系统规则配置。
- 日志管理。
- 健康检查。

### 2.2 接口测试

- 请求参数校验。
- JWT 鉴权。
- 管理员权限校验。
- 统一响应格式。
- 分页返回格式。
- 错误码和错误信息。

### 2.3 并发测试

- 多个用户同时预约同一场地同一时间段。
- Redis 锁过期后再次预约。
- MySQL 已存在预约时重复提交。

### 2.4 非功能测试

- 页面基础可用性。
- 常规接口响应时间。
- 数据库连接状态。
- Redis 连接状态。
- 异常情况下错误提示是否明确。

## 3. 测试环境

建议测试环境如下：

| 项目 | 配置 |
| --- | --- |
| 操作系统 | macOS / Linux / Windows |

## 7. 并发测试用例

### 7.1 同一时间段并发预约

用例编号：TC-CONCURRENT-001

测试步骤：

1. 准备两个启用用户 `user01` 和 `user02`。
2. 两个用户同时提交预约请求。
3. 请求目标为同一场地、同一日期、同一开始时间和结束时间。
4. 查看接口返回和数据库记录。

预期结果：

- 只有一个请求能创建待支付预约订单。
- 另一个请求失败，提示时间段已被占用或正在预约。
- MySQL 中只存在一条有效预约。
- 创建待支付预约不扣会员余额；只有支付成功才扣款。
- Redis 锁不会导致永久占用。
- 对于不同起止时间但实际重叠的请求，MySQL 事务层仍应阻止重复预约。

### 7.2 Redis 锁过期后释放

用例编号：TC-CONCURRENT-002

测试步骤：

1. 设置较短的预约锁超时时间。
2. 模拟用户获取锁但未完成确认。
3. 等待 Redis key 过期。
4. 再次提交同一时间段预约。

预期结果：

- 锁过期后不再阻止新请求。
- 如果 MySQL 没有有效预约，则新预约可以成功。
- 如果 MySQL 已有有效预约，则仍然失败。

### 7.3 数据库最终校验

用例编号：TC-CONCURRENT-003

测试步骤：

1. 手动在 MySQL 中插入一条 confirmed 预约。
2. 清空对应 Redis 锁。
3. 提交相同时间段预约。

预期结果：

- 后端通过 MySQL 校验发现冲突。
- 预约失败。
- 不产生重复预约记录。
