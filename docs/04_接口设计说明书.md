# 接口设计说明书

## 1. 接口设计原则

BF羽毛球馆管理平台后端基于 Tornado 提供 REST API，前端通过 Axios 调用接口。接口设计遵循以下原则：

- 使用 JSON 作为请求和响应格式。
- 需要登录的接口通过 JWT 鉴权。
- 管理员接口统一放在 `/api/admin` 前缀下。
- 列表接口支持分页。
- 业务错误返回明确的错误码和错误信息。
- 后端统一封装响应格式。

## 2. 基础约定

### 2.1 请求地址

本地开发环境建议：

```text
前端地址：http://localhost:5188
后端地址：http://localhost:8000
接口前缀：http://localhost:8000/api
```

### 2.2 请求头

登录后访问受保护接口时，需要携带：

```text
Authorization: Bearer <token>
Content-Type: application/json
```

### 2.3 统一响应格式

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

失败响应：

```json
{
  "code": 400,
  "message": "请求参数错误",
  "data": null
}
```

分页响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "page_size": 10
  }
}
```

### 2.4 常用错误码

| code | HTTP 状态 | 说明 |
| --- | --- | --- |
| 0 | 200 | 成功 |
| 400 | 400 | 请求参数错误 |
| 401 | 401 | 未登录或登录过期 |
| 403 | 403 | 无权限 |
| 404 | 404 | 资源不存在 |
| 409 | 409 | 业务冲突 |
| 500 | 500 | 系统内部错误 |

## 3. 认证接口

### 3.1 用户注册

```text
POST /api/auth/register
```

请求参数：

```json
{
  "username": "zhangsan",
  "password": "123456",
  "nickname": "张三",
  "contact": "13800000000"
}
```

响应数据：

```json
{
  "id": 1,
  "username": "zhangsan",
  "nickname": "张三",
  "role": "user"
}
```

业务规则：

- 用户名不能为空。
- 用户名不能重复。
- 密码需要满足基础长度要求。
- 新注册用户默认角色为 `user`。

### 3.2 用户登录

```text
POST /api/auth/login
```

请求参数：

```json
{
  "username": "zhangsan",
  "password": "123456"
}
```

响应数据：

```json
{
  "token": "jwt-token",
  "user": {
    "id": 1,
    "username": "zhangsan",
    "nickname": "张三",
    "role": "user"
  }
}
```

业务规则：

- 用户不存在或密码错误时返回登录失败。
- 被禁用用户不能登录。
- 登录成功后更新最近登录时间。

### 3.3 获取当前用户信息

```text
GET /api/auth/profile
```

权限：登录用户。

响应数据：

```json
{
  "id": 1,
  "username": "zhangsan",
  "nickname": "张三",
  "role": "user",
  "contact": "13800000000",
  "status": 1
}
```

### 3.4 修改个人信息

```text
PUT /api/auth/profile
```

权限：登录用户。

请求参数：

```json
{
  "nickname": "新的昵称",
  "contact": "13900000000"
}
```

### 3.5 修改密码

```text
PUT /api/auth/password
```

权限：登录用户。

请求参数：

```json
{
  "old_password": "123456",
  "new_password": "abcdef"
}
```

业务规则：

- 必须校验旧密码。
- 新密码需要重新加密后保存。

## 4. 场地接口

### 4.1 查询场地列表

```text
GET /api/courts
```

权限：登录用户。

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| status | 否 | 场地状态 |
| page | 否 | 页码 |
| page_size | 否 | 每页数量 |

响应数据：

```json
{
  "items": [
    {
      "id": 1,
      "court_no": "A01",
      "court_name": "一号场",
      "status": 1,
      "description": "靠近入口"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 10
}
```

### 4.2 查询场地时间段状态

```text
GET /api/courts/{court_id}/slots
```

权限：登录用户。

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| date | 是 | 日期，格式 YYYY-MM-DD |

响应数据：

```json
{
  "court_id": 1,
  "date": "2026-05-15",
  "slots": [
    {
      "start_time": "09:00",
      "end_time": "10:00",
      "status": "available"
    },
    {
      "start_time": "10:00",
      "end_time": "11:00",
      "status": "reserved"
    }
  ]
}
```

时间段状态：

| 状态 | 说明 |
| --- | --- |
| available | 可预约 |
| locked | 已被临时锁定 |
| reserved | 已预约 |
| disabled | 场地不可用 |

## 5. 预约接口

### 5.1 创建预约

```text
POST /api/reservations
```

权限：登录用户。

请求参数：

```json
{
  "court_id": 1,
  "reserve_date": "2026-05-15",
  "start_time": "09:00",
  "end_time": "10:00",
  "remark": "周五上午训练"
}
```

响应数据：

```json
{
  "id": 1001,
  "reservation_no": "R202605150001",
  "court_id": 1,
  "reserve_date": "2026-05-15",
  "time_slot": "09:00-10:00",
  "status": "confirmed"
}
```

业务规则：

- 用户必须处于启用状态。
- 场地必须处于启用状态。
- 预约日期不能早于当前日期。
- 预约日期不能超过可提前预约天数。
- 单次预约时长不能超过系统配置。
- 同一用户每日预约次数不能超过系统配置。
- 同一场地同一时间段不能重复预约。
- 预约前必须先获取 Redis 锁。

### 5.2 查询我的预约

```text
GET /api/reservations/my
```

权限：登录用户。

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| status | 否 | 预约状态 |
| page | 否 | 页码 |
| page_size | 否 | 每页数量 |

响应数据：

```json
{
  "items": [
    {
      "id": 1001,
      "reservation_no": "R202605150001",
      "court_name": "一号场",
      "reserve_date": "2026-05-15",
      "time_slot": "09:00-10:00",
      "status": "confirmed"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 10
}
```

### 5.3 取消预约

```text
PUT /api/reservations/{reservation_id}/cancel
```

权限：登录用户。

请求参数：

```json
{
  "reason": "临时有事"
}
```

业务规则：

- 用户只能取消自己的预约。
- 已完成、已过期、已取消的预约不能重复取消。
- 超过取消时间规则的预约不能取消。
- 取消成功后更新状态为 `canceled`。

## 7. 管理员接口

所有管理员接口都需要 `admin` 角色。

### 7.1 用户管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/users` | 查询用户列表 |
| POST | `/api/admin/users` | 新增用户 |
| PUT | `/api/admin/users/{user_id}` | 修改用户 |
| PUT | `/api/admin/users/{user_id}/status` | 启用或禁用用户 |
| PUT | `/api/admin/users/{user_id}/role` | 修改用户角色 |

修改用户状态请求示例：

```json
{
  "status": 0
}
```

### 7.2 场地管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/courts` | 查询场地列表 |

| PUT | `/api/admin/courts/{court_id}` | 修改场地 |
| PUT | `/api/admin/courts/{court_id}/status` | 启用或停用场地 |

新增场地请求示例：

```json
{
  "court_no": "A01",
  "court_name": "一号场",
  "description": "靠近入口",
  "status": 1
}
```

### 7.3 预约管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/reservations` | 查询全部预约 |
| GET | `/api/admin/reservations/{reservation_id}` | 查询预约详情 |
| PUT | `/api/admin/reservations/{reservation_id}/status` | 修改预约状态 |

### 7.4 公告管理

| 方法 | 路径 | 说明 |

## 8. 前端请求封装建议

前端可在 Axios 拦截器中统一处理：

- 自动添加 `Authorization` 请求头。
- 登录过期后跳转登录页。
- 统一展示错误信息。
- 统一解析 `code/message/data`。

## 9. 接口验收标准

- 所有接口返回统一 JSON 格式。
- 登录成功后能正确访问受保护接口。
- 普通用户访问管理员接口时返回 403。
- 未登录访问受保护接口时返回 401。
- 创建预约时能正确处理重复预约冲突。
- 列表接口支持分页并返回总数。
- 错误场景能返回明确的错误信息。
