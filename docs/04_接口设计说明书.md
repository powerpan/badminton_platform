# 接口设计说明书

## 1. 接口设计原则

BF羽毛球馆管理平台后端基于 Tornado 提供 REST API，前端通过 Axios 调用接口。接口设计遵循以下原则：

- 使用 JSON 作为请求和响应格式。
- 需要登录的接口通过 JWT 鉴权。
- 管理员接口统一放在 `/api/admin` 前缀下。
- 列表接口支持分页。
- 业务错误返回明确的错误码和错误信息。
- 后端统一封装响应格式。

## 2. 基础约定

### 2.1 请求地址

本地开发环境建议：

```text
前端地址：http://localhost:5188
后端地址：http://localhost:8000
接口前缀：http://localhost:8000/api
```

### 2.2 请求头

登录后访问受保护接口时，需要携带：

```text
Authorization: Bearer <token>
Content-Type: application/json
```

### 2.3 统一响应格式

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

失败响应：

```json
{
  "code": 400,
  "message": "请求参数错误",
  "data": null
}
```

分页响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "page_size": 10
  }
}
```

### 2.4 常用错误码

| code | HTTP 状态 | 说明 |
| --- | --- | --- |
| 0 | 200 | 成功 |
| 400 | 400 | 请求参数错误 |
| 401 | 401 | 未登录或登录过期 |
| 403 | 403 | 无权限 |
| 404 | 404 | 资源不存在 |
| 409 | 409 | 业务冲突 |
| 423 | 423 | 登录失败次数过多，账号短暂锁定 |
| 500 | 500 | 系统内部错误 |

## 3. 认证接口

### 3.1 获取图形验证码

```text
GET /api/auth/captcha
```

响应数据：

```json
{
  "captcha_id": "uuid",
  "image_data": "data:image/svg+xml;base64,...",
  "expires_in": 300
}
```

业务规则：

- 验证码保存在 Redis，默认 300 秒过期。
- 登录、注册和找回密码会校验 `captcha_id` 和 `captcha_code`。
- 验证码单次使用，校验成功或失败后都会失效。

### 3.2 用户注册

```text
POST /api/auth/register
```

请求参数：

```json
{
  "username": "zhangsan",
  "password": "123456",
  "nickname": "张三",
  "contact": "13800000000",
  "captcha_id": "uuid",
  "captcha_code": "ABCD"
}
```

响应数据：

```json
{
  "id": 1,
  "username": "zhangsan",
  "nickname": "张三",
  "role": "user"
}
```

业务规则：

- 用户名不能为空。
- 用户名不能重复。
- 密码需要满足基础长度要求。
- 新注册用户默认角色为 `user`。
- 必须提供有效验证码。

### 3.3 用户登录

```text
POST /api/auth/login
```

请求参数：

```json
{
  "username": "zhangsan",
  "password": "123456",
  "captcha_id": "uuid",
  "captcha_code": "ABCD"
}
```

响应数据：

```json
{
  "token": "jwt-token",
  "access_token": "jwt-token",
  "refresh_token": "refresh-token",
  "user": {
    "id": 1,
    "username": "zhangsan",
    "nickname": "张三",
    "role": "user",
    "must_change_password": false
  }
}
```

业务规则：

- 用户不存在或密码错误时返回登录失败。
- 被禁用用户不能登录。
- 登录成功后更新最近登录时间。
- 连续登录失败达到阈值后，Redis 会短暂锁定该用户名。
- refresh token 存入 Redis，退出登录或刷新轮换后旧 token 失效。
- 必须提供有效验证码，验证码错误不会计入密码失败次数。

### 3.4 刷新登录态

```text
POST /api/auth/refresh
```

请求参数：

```json
{
  "refresh_token": "refresh-token"
}
```

响应数据与登录接口一致。后端会轮换 refresh token，旧 refresh token 会失效。

### 3.5 退出登录

```text
POST /api/auth/logout
```

请求参数：

```json
{
  "refresh_token": "refresh-token"
}
```

业务规则：

- 后端删除 Redis 中对应 refresh token。
- 前端清理本地 token、refresh token 和用户信息。

### 3.6 申请找回密码

```text
POST /api/auth/password-reset/request
```

请求参数：

```json
{
  "username": "zhangsan",
  "contact": "13800000000",
  "captcha_id": "uuid",
  "captcha_code": "ABCD"
}
```

响应数据：

```json
{
  "reset_token": "password-reset-token",
  "expires_in": 600
}
```

业务规则：

- 用户名和联系方式必须与用户资料一致。
- 账号被禁用时不能找回密码。
- 重置凭证保存在 Redis，默认 600 秒过期。
- 当前版本用于本地演示，重置凭证直接返回给前端；后续可替换为邮件或短信发送。

### 3.7 确认重置密码

```text
POST /api/auth/password-reset/confirm
```

请求参数：

```json
{
  "reset_token": "password-reset-token",
  "new_password": "abcdef"
}
```

业务规则：

- 重置凭证必须存在且未过期。
- 新密码长度不能少于 6 位。
- 密码重置成功后会删除该用户旧 refresh token，旧登录态不能继续刷新。

### 3.8 获取当前用户信息

```text
GET /api/auth/profile
```

权限：登录用户。

响应数据：

```json
{
  "id": 1,
  "username": "zhangsan",
  "nickname": "张三",
  "role": "user",
  "contact": "13800000000",
  "status": 1,
  "must_change_password": false
}
```

### 3.9 修改个人信息

```text
PUT /api/auth/profile
```

权限：登录用户。

请求参数：

```json
{
  "nickname": "新的昵称",
  "contact": "13900000000"
}
```

### 3.10 修改密码

```text
PUT /api/auth/password
```

权限：登录用户。

请求参数：

```json
{
  "old_password": "123456",
  "new_password": "abcdef"
}
```

业务规则：

- 必须校验旧密码。
- 新密码需要重新加密后保存。
- 修改成功后会删除该用户旧 refresh token。

## 5. 预约接口

### 5.1 创建预约

```text
POST /api/reservations
```

权限：登录用户。

请求参数：

```json
{
  "court_id": 1,
  "reserve_date": "2026-05-15",
  "start_time": "09:00",
  "end_time": "10:00",
  "remark": "周五上午训练"
}
```

响应数据：

```json
{
  "id": 1001,
  "reservation_no": "R202605150001",
  "court_id": 1,
  "reserve_date": "2026-05-15",
  "time_slot": "09:00-10:00",
  "status": "confirmed"
}
```

业务规则：

- 用户必须处于启用状态。
- 场地必须处于启用状态。
- 预约日期不能早于当前日期。
- 预约日期不能超过可提前预约天数。
- 单次预约时长不能超过系统配置。
- 同一用户每日预约次数不能超过系统配置。
- 同一场地同一时间段不能重复预约。
- 预约前必须先获取 Redis 锁。
- Redis 锁成功后，后端会在 MySQL 短事务内重新校验用户、场地、每日次数和时间重叠。
- 即使两个请求的起止时间不同，只要满足 `new_start < old_end AND new_end > old_start`，仍返回 `409`。

### 5.2 查询我的预约

```text
GET /api/reservations/my
```

权限：登录用户。

查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| status | 否 | 预约状态 |
| page | 否 | 页码 |
| page_size | 否 | 每页数量 |

响应数据：

```json
{
  "items": [
    {
      "id": 1001,
      "reservation_no": "R202605150001",
      "court_name": "一号场",
      "reserve_date": "2026-05-15",
      "time_slot": "09:00-10:00",
      "status": "confirmed"
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 10
}
```

### 5.3 取消预约

```text
PUT /api/reservations/{reservation_id}/cancel
```

权限：登录用户。

请求参数：

```json
{
  "reason": "临时有事"
}
```

业务规则：

- 用户只能取消自己的预约。
- 已完成、已过期、已取消的预约不能重复取消。
- 超过取消时间规则的预约不能取消。
- 取消成功后更新状态为 `canceled`。

## 7. 管理员接口

所有管理员接口都需要 `admin` 角色。

### 7.1 用户管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/users` | 查询用户列表 |
| POST | `/api/admin/users` | 新增用户 |
| PUT | `/api/admin/users/{user_id}/status` | 启用或禁用用户 |
| PUT | `/api/admin/users/{user_id}/role` | 修改用户角色 |
| PUT | `/api/admin/users/{user_id}/password` | 重置用户密码 |

修改用户状态请求示例：

```json
{
  "status": 0
}
```

业务规则：

- 管理员不能在用户管理中禁用当前登录账号。
- 禁用用户前会检查该用户未来的 `pending/confirmed` 预约。
- 如果仍存在未来有效预约，接口返回 `409`，需要先取消预约再禁用用户。
- 前端会对禁用、启用、角色修改和重置密码进行二次确认。

### 7.2 场地管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/courts` | 查询场地列表 |
| POST | `/api/admin/courts` | 新增场地 |
| PUT | `/api/admin/courts/{court_id}` | 修改场地 |
| PUT | `/api/admin/courts/{court_id}/status` | 启用或停用场地 |

新增场地请求示例：

```json
{
  "court_no": "A01",
  "court_name": "一号场",
  "description": "靠近入口",
  "status": 1
}
```

业务规则：

- 停用场地前会检查该场地未来的 `pending/confirmed` 预约。
- 如果仍存在未来有效预约，接口返回 `409`，需要先取消预约再停用场地。
- 通过编辑场地把状态改为停用时，也执行同样的未来预约检查。
- 前端会对停用、启用和编辑停用场地进行二次确认。

### 7.3 预约管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/reservations` | 查询全部预约 |
| GET | `/api/admin/reservations/{reservation_id}` | 查询预约详情 |
| PUT | `/api/admin/reservations/{reservation_id}/cancel` | 管理员取消预约 |

业务规则：

- 已取消、已完成、已过期的预约不能再次取消。
- 管理员取消预约前，前端会进行二次确认。

### 7.4 公告管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/announcements` | 查询公告列表 |
| POST | `/api/admin/announcements` | 发布公告 |
| PUT | `/api/admin/announcements/{announcement_id}` | 编辑公告 |
| PUT | `/api/admin/announcements/{announcement_id}/status` | 显示或隐藏公告 |

业务规则：

- 当前实现采用状态隐藏，不提供物理删除接口。
- 隐藏或显示公告前，前端会进行二次确认。

### 7.5 统计分析

统计分析接口已实现，均要求管理员权限。统计接口会先修正已结束预约状态，将已结束的 `confirmed` 更新为 `completed`。

通用查询参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| date_from | 否 | 开始日期，格式 `YYYY-MM-DD`，默认今天 |
| date_to | 否 | 结束日期，格式 `YYYY-MM-DD`，默认今天后 6 天 |

接口列表：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/statistics/overview` | 统计总览 |
| GET | `/api/admin/statistics/courts` | 场地使用率统计 |
| GET | `/api/admin/statistics/time-slots` | 热门时间段统计 |
| GET | `/api/admin/statistics/users` | 用户活跃度统计 |

统计总览返回字段：

```json
{
  "date_from": "2026-05-15",
  "date_to": "2026-05-21",
  "total_users": 10,
  "enabled_users": 9,
  "total_courts": 3,
  "enabled_courts": 3,
  "reservation_total": 18,
  "today_reservations": 2,
  "active_users": 5,
  "capacity_slots": 252,
  "occupied_slots": 18,
  "utilization_rate": 7.14
}
```

说明：

- `capacity_slots` 按启用场地数、营业时间、时间段间隔和日期范围计算。
- `occupied_slots` 统计 `pending/confirmed/completed` 状态。
- 时间段和用户统计接口支持 `limit` 参数。

### 7.6 系统规则配置

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/configs` | 查询配置列表 |
| PUT | `/api/admin/configs/{config_key}` | 修改配置 |

修改配置请求示例：

```json
{
  "config_value": "300"
}
```

前端保存规则配置前会进行二次确认，后端仍以配置校验结果为准。

当前默认配置项：

| 配置键 | 默认值 | 说明 |
| --- | --- | --- |
| `business_start_time` | `09:00` | 每日营业开始时间 |
| `business_end_time` | `21:00` | 每日营业结束时间 |
| `slot_interval_minutes` | `60` | 预约时间段间隔 |
| `advance_reservation_days` | `7` | 可提前预约天数 |
| `daily_reservation_limit` | `3` | 用户每日最大预约次数 |
| `max_reservation_hours` | `2` | 单次最大预约小时数 |
| `reservation_lock_ttl_seconds` | `300` | Redis 预约锁超时时间 |

### 7.7 日志与健康检查

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/health` | 查询系统健康状态 |

操作日志查询参数：

| 参数 | 必填 | 说明 |

| date_to | 否 | 结束日期，格式 `YYYY-MM-DD` |
| page | 否 | 页码 |
| page_size | 否 | 每页数量 |

当前会写入日志的管理员操作：

健康检查响应示例：

```json
{
  "api": { "status": "ok" },
  "mysql": { "status": "ok" },
  "redis": { "status": "ok" },
  "env": "dev",
  "checked_at": "2026-05-15 10:00:00"

```

## 8. 前端请求封装建议

前端可在 Axios 拦截器中统一处理：

- 自动添加 `Authorization` 请求头。
- 登录过期后跳转登录页。
- 统一展示错误信息。
- 统一解析 `code/message/data`。

## 9. 接口验收标准

- 所有接口返回统一 JSON 格式。
- 登录成功后能正确访问受保护接口。
- 普通用户访问管理员接口时返回 403。
- 未登录访问受保护接口时返回 401。
- 创建预约时能正确处理重复预约冲突。
- 列表接口支持分页并返回总数。
- 错误场景能返回明确的错误信息。
