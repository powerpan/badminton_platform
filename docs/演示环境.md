# 独立演示环境

`create_demo.py` 只创建新库，默认预览，不连接或修改数据库。它不会修改 `backend/.env`，也不包含固定演示密码。

## 创建与重置

在项目根目录执行：

```bash
backend/.venv/bin/python scripts/create_demo.py --database badminton_demo_presentation
backend/.venv/bin/python scripts/create_demo.py --database badminton_demo_presentation --apply
```

第二条命令会在终端隐藏输入演示账号密码，要求至少 8 位。也支持由本地环境变量 `BF_DEMO_PASSWORD` 提供；不要把密码写入仓库或命令历史。

生成三个账号：`demo_manager`（管理员）、`demo_player`、`demo_partner`。它们使用本次输入的密码，数据库只保存哈希。

数据库名必须以 `badminton_demo_` 开头，后缀只能是小写字母、数字和下划线。脚本拒绝当前业务库，也拒绝任何已存在的库。MySQL 连接配置从现有 `backend/.env` 读取，数据库建库权限不足时需要使用有权限的本地数据库账号。

**重置采用换新库名的方式**：停止演示进程，使用例如 `badminton_demo_presentation_02` 重新生成，再将演示进程指向新库。脚本不会删除或覆盖旧库。若初始化中途失败，也使用新库名重试；失败的新库保留供排查。

## 数据内容

- 58 条预约：待支付、已确认、已结束、已取消、已过期；历史记录超过一页。
- 下一场和更晚的已确认预约故意按相反顺序插入，可验证“下一场”不依赖最近一页。
- 账户初始演示余额、已支付预约对应的扣费与积分流水，余额可与流水汇总核对。
- 两条公告、两项未来活动、一条报名、两条球友动态和欢迎通知。
- 场地、规则和商品沿用初始化脚本的默认结构与资料。商品图片由前端按类别显示明确标注的示意图。

日期默认为运行当天，也可用 `--date YYYY-MM-DD` 指定。待支付订单会按真实时间过期，固定旧日期只适合测试，不适合现场演示。

## 使用演示库

演示时单独启动后端进程，使用新的数据库名，并配置独立的 Redis 实例或确认空闲的专用逻辑库。不要让演示和当前业务服务共用预约锁、登录状态和缓存。前端的 API 地址需指向该演示服务。

本轮没有把正在运行的项目切换到演示库，也没有改变任何现有账号的密码。
