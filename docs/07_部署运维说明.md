# 部署运维说明

## 1. 文档目的

本文档说明 BF羽毛球馆管理平台的本地开发环境、部署配置、启动流程、健康检查和常见运维操作。当前项目采用前后端分离架构，后端基于 Tornado，前端基于 Vue3，数据服务包括 MySQL 和 Redis。

## 2. 环境要求

### 2.1 基础软件

| 软件 | 建议版本 | 用途 |
| --- | --- | --- |
| Node.js | 18.x 或以上 | 运行 Vue3 前端 |
| Python | 3.10 或以上 | 运行 Tornado 后端 |
| MySQL | 8.x | 保存业务数据 |
| Redis | 6.x 或以上 | 预约锁和缓存 |
| Git | 2.x | 版本管理 |

### 2.2 本地端口

| 服务 | 默认端口 | 说明 |
| --- | --- | --- |
| Vue3 | 5188 | 前端开发服务 |
| Tornado | 8000 | 后端 API 服务 |
| MySQL | 3306 | 数据库 |
| Redis | 6379 | 缓存和预约锁 |

## 4. 配置项说明

后端建议通过 `.env` 或配置文件读取环境变量。

### 4.1 后端配置

| 配置项 | 示例值 | 说明 |
| --- | --- | --- |
| APP_ENV | dev | 运行环境 |
| APP_PORT | 8000 | 后端端口 |
| JWT_SECRET | change-me | JWT 密钥 |
| JWT_EXPIRE_SECONDS | 86400 | JWT 过期时间 |
| JWT_REFRESH_EXPIRE_SECONDS | 604800 | refresh token 过期时间 |
| LOGIN_FAIL_MAX | 5 | 登录失败锁定阈值 |
| LOGIN_FAIL_WINDOW_SECONDS | 600 | 登录失败计数窗口 |
| LOGIN_LOCK_SECONDS | 600 | 登录失败锁定时间 |
| CAPTCHA_EXPIRE_SECONDS | 300 | 图形验证码过期时间 |
| PASSWORD_RESET_EXPIRE_SECONDS | 600 | 找回密码重置凭证过期时间 |
| MYSQL_HOST | 127.0.0.1 | MySQL 地址 |
| MYSQL_PORT | 3306 | MySQL 端口 |
| MYSQL_USER | root | MySQL 用户 |
| MYSQL_PASSWORD | root | MySQL 密码 |
| MYSQL_DATABASE | badminton_platform | 数据库名 |
| REDIS_HOST | 127.0.0.1 | Redis 地址 |
| REDIS_PORT | 6379 | Redis 端口 |
| REDIS_DB | 0 | Redis DB |

### 4.2 前端配置

前端建议使用 `.env.development`：

```text
VITE_API_BASE_URL=http://localhost:8000/api
```

生产环境可使用 `.env.production`：

```text
VITE_API_BASE_URL=/api
```

## 5. 本地开发启动流程

### 5.1 启动 MySQL

确认 MySQL 已启动，并创建数据库：

```sql
CREATE DATABASE badminton_platform DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

导入初始化 SQL：

```text
mysql -uroot -p badminton_platform < sql/init.sql
```

如果是全新环境，也可以直接执行包含建库语句的初始化脚本：

```text
mysql -uroot -p < sql/init.sql
```

已有数据库升级到当前阶段时，按顺序执行：

```text
mysql -uroot -p badminton_platform < scripts/upgrade_phase1_court_assets.sql
mysql -uroot -p badminton_platform < scripts/upgrade_phase2_member_accounts.sql
mysql -uroot -p badminton_platform < scripts/upgrade_phase3_notifications.sql
mysql -uroot -p badminton_platform < scripts/upgrade_phase4_marketplace.sql
```

### 5.2 启动 Redis

确认 Redis 服务已启动：

```text
redis-cli ping
```

预期返回：

```text
PONG
```

### 5.3 一键启动开发服务

推荐在本地开发时直接使用根目录脚本统一启停前后端：

```text
./start-dev.command
./stop-dev.command
```

脚本会写入 `logs/backend.log`、`logs/frontend.log`，并在启动时检查后端健康状态和前端端口。

### 5.4 启动后端

进入后端目录：

```text
cd backend
```

创建虚拟环境：

```text
python -m venv .venv
```

安装依赖：

```text
.venv/bin/pip install -r requirements.txt
```

启动服务：

```text
.venv/bin/python app.py
```

后端启动后应监听：

```text
http://localhost:8000
```

### 5.5 启动前端

进入前端目录：

```text
cd frontend
```

安装依赖：

```text
npm install
```

启动服务：

```text
npm run dev
```

前端启动后应监听：

```text
http://localhost:5188
```

## 6. 健康检查

后端应提供健康检查接口：

```text
GET /api/health
GET /api/admin/health
```

检查内容：

- API 服务是否正常。
- MySQL 是否可连接。
- Redis 是否可连接。

返回示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "api": { "status": "ok" },
    "mysql": { "status": "ok" },
    "redis": { "status": "ok" },
    "env": "dev",
    "checked_at": "2026-05-15 10:00:00"
  }
}
```

## 7. 日志管理

### 7.1 后端日志

后端建议记录：

- 服务启动日志。
- 请求错误日志。
- 数据库连接错误。
- Redis 连接错误。

- 用户状态修改。
- 用户角色修改。
- 会员账户调整。
- 管理员重置密码。
- 场地新增、编辑、停用。
- 预约取消。
- 公告发布、编辑、隐藏。
- 全员群发站内通知。
- 活动创建、编辑、显示、隐藏。
- 球友圈动态隐藏。
- 商城商品创建、编辑、上下架。
- 商城订单完成、取消退款。
- 系统配置修改。

## 8. 生产部署建议

生产环境可采用：

```text
Nginx
  -> Vue3 静态文件
  -> /api 反向代理到 Tornado

Tornado
  -> MySQL
  -> Redis
```

### 8.1 前端构建

```text
cd frontend
npm run build
```

构建产物通常位于：

```text
frontend/dist
```

### 8.2 后端运行

生产环境可以使用进程管理工具运行 Tornado，例如 systemd、supervisor 或 Docker。

需要注意：

- 不要在生产环境使用默认 JWT 密钥。
- 数据库密码不要写死在代码中。
- Redis 和 MySQL 不应暴露到公网。
- 后端错误信息不应直接返回堆栈给前端。

### 8.3 Nginx 反向代理示例

```nginx
server {
    listen 80;
    server_name example.com;

    root /var/www/badminton_platform/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

## 9. 备份与恢复

### 9.1 数据库备份

建议定期备份 MySQL：

```text
mysqldump -uroot -p badminton_platform > backup.sql
```

### 9.2 数据库恢复

```text
mysql -uroot -p badminton_platform < backup.sql
```

### 9.3 Redis 数据

当前系统中 Redis 主要用于预约锁和短期缓存，核心业务数据以 MySQL 为准。Redis 数据丢失不应造成核心预约数据丢失。

## 10. 常见问题处理

### 10.1 后端无法连接 MySQL

排查步骤：

1. 确认 MySQL 服务是否启动。
2. 确认数据库名、用户名和密码是否正确。
3. 确认端口是否为 3306。
4. 使用 `SELECT 1` 验证连接。

### 10.2 后端无法连接 Redis

排查步骤：

1. 执行 `redis-cli ping`。
2. 确认 Redis 地址和端口。
3. 确认 Redis 是否设置密码。
4. 查看后端 Redis 连接配置。

### 10.3 前端请求接口失败

排查步骤：

1. 确认后端服务是否启动。
2. 确认 `VITE_API_BASE_URL` 是否正确。
3. 查看浏览器控制台网络请求。
4. 检查是否存在跨域问题。
5. 检查请求是否携带 JWT。

### 10.4 预约一直显示被占用

排查步骤：

1. 查询 MySQL 是否已有有效预约。
2. 查询 Redis 是否存在对应锁 key。
3. 检查锁 TTL 是否正常。
4. 检查取消预约是否更新状态。
5. 检查时间段格式是否一致。

## 11. 上线检查清单

- MySQL 表结构已初始化。
- 管理员账号已创建。
- Redis 服务可用。
- JWT 密钥已替换为生产密钥。
- 前端生产 API 地址正确。
- 后端日志路径可写。
- Nginx 路由转发正常。
- 健康检查接口返回正常。
- 普通用户预约流程测试通过。
- 管理员后台核心功能测试通过。
